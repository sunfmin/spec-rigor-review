## functional_test

Task: run the review on a small Go fixture containing (a) an `Order` whose state is a
`Status` string plus `Paid` and `Shipped` booleans, with a comment stating "a shipped
order is always paid"; (b) transitions spread across handlers that mix the rule with
database calls, where `Ship` does not check payment; (c) the `Order` shape written by
hand in both Go and `api/openapi.yaml`, with the two disagreeing; (d) a Makefile that
runs `oasdiff breaking` without `--fail-on` and runs `quint run` under a comment
calling it formal verification, against a model whose invariant any state satisfies.

Success condition, all must hold:

1. Schema and type candidates include an enumeration for the order state and a single
   source for the `Order` shape, and report the disagreement between the two copies.
2. Verification candidates include a model of the order state machine with the
   invariant "a shipped order is always paid".
3. Refactors include extracting the transitions into a pure function and name the
   check it unlocks.
4. Weak existing checks flags `oasdiff breaking` for the missing `--fail-on`, and the
   Quint check for sampling presented as verification or for the weak invariant.
5. The report ends with three findings to do first.
6. No file in the fixture was modified.
